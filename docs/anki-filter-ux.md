# 漫画词汇筛选 UX 与实现

核对日期：2026-10-02。当前入口为漫画“分词 → Anki 制卡”，保留五步导航：规则筛词、可选 AI 筛选、手动筛词、词卡生成、制卡。

第 4 步默认 A3，提供 A0–A4 消耗档位、单次新增卡数与生成阶段 token 预算、调用预估和旧 R0–R3 兼容入口。流水线自动选择例句、读取用户已导入词典、校验并尝试修复；第 5 步分为可导出、待审和暂缓，显示具体问题字段，允许先导出已通过卡。不再要求用户逐卡确认全部新档位卡片。档位职责与验证边界见 [Anki Harness](anki-harness.md)。

下方是 2026-09-29 的 F/R 五步设计记录；其中 R 档位生成与全卡审核描述仅适用于旧任务，当前 A 档位以上述说明为准。

## 旧界面证据与问题

2026-09-29 在 macOS 上运行 `ARALE_SMOKE_STUDY_SCREENSHOT=… npm run smoke`，用应用自带示例漫画进入筛选页并截取[当前界面](../screenshots/10-anki-filter-current.png)；冒烟流程 197/197。截图处于假 LLM 筛选完成后的测试状态，五级 JLPT 和未分级全勾，不代表新书默认配置。结合当前组件与 CSS，可确认：

1. **步骤没有主次**：规则、LLM、制卡、导出同在一个最高 280px 的滚动区域。截图首屏只能看到规则的上半段；规则结果与下一步都要在内部继续滚动。下方候选列表又独立滚动，难以同时核对规则和词。
2. **“筛选”有三种含义**：上方的规则会修改正式选择，LLM 会给出判断，下方的等级/搜索/“只看已选”只改变列表显示；但都叫筛选。“选择筛选结果”容易被理解为应用规则，实际是批量选择当前显示项。
3. **看不清改动的后果**：四层的余量数字排在规则之后，缺少醒目的“40 个 → 预计保留 X 个”。逐词看不到被哪条规则排除；“报告式严格规则”一次启用多条条件，但按钮本身不解释具体影响。
4. **人工决定被分散**：候选行复选框、详情里的“排除”和“手动保留”是三个位置、不同含义。用户需要先理解优先级，才敢保留角色名或排除 OCR 错词。
5. **状态反馈互相抢注意力**：顶部缺读音/释义提示在筛词时出现，LLM 的保留/待审/排除计数与“已选”并列；用户难判断当前是在预览、正式应用，还是已经可以制卡。截图中多处说明文字灰度较浅；实际对比度与键盘流程还需专门测量。

## 当前信息架构

把筛词变成**一次只处理一个决定**的流程，顶部始终显示进度与结果：

1. **规则筛词**：配置条件、实时预览保留/排除及原因，明确应用。
2. **AI 语境筛选（可跳过）**：对已应用的词单做 F1/F2/F3 判断；选择模型并运行或直接跳过。
3. **手动筛词**：只决定词是否纳入，用“手动保留 / 手动排除”两个可撤销操作处理待审与例外。
4. **AI 释义生成**：像第 2 步一样选 R0/R1/R2/R3；翻译引擎与 R1–R3 的 LLM 配置排在档位下方。R0 不调用 LLM。
5. **制卡**：逐卡编辑全部可见内容，独立选择不带图、文字框截图或整页漫画，最后导出；改变配图不重跑第 4 步。

页面顶部用紧凑步骤导航显示当前步骤；只展示当前步骤的主内容，其他步骤折叠为可返回的摘要。用户随时能返回规则页查看已应用条件，但改规则须重新预览并应用。旧 LLM 检查点存在时，明确说明“已完成 72/958 个判断”，给出“继续原任务”和“放弃 72 项结果并应用新规则”两个动作，不出现原因不明的禁用按钮。

### 第 1 步：规则筛词

桌面宽度下采用左右布局：左侧约 320–380px 为规则，右侧为实时结果词表；词的原句、读音、JLPT、次数、跨页数、词频及排除原因在右侧详情区查看。窄窗口改为规则在上、结果在下。移除现有工作流的 280px 限高；主页面使用正常纵向滚动，规则摘要和底部动作保持可见。

规则按用户要回答的问题命名，默认只展开第一组，其他组显示是否启用与本组新增排除数：

| 组 | 首屏文案与控件 | 进阶内容 |
|---|---|---|
| 学哪些等级？ | N5–N1 独立选择，当前默认 N3/N2/N1；“未收录等级”与“等级冲突”分开说明 | JLPT 来源及“仅供参考”说明 |
| 排除哪些明显无用词？ | 人名/专名、数词、分词器未知词分别开关 | 词性限制和本书排除词清单；旧候选缺数据时显示“需重新生成候选” |
| 只保留重复出现的词？ | 关闭 / 至少 2 次 / 自定义次数 | 说明单次但有价值的词可手动保留 |
| 参考通用词频？ | 默认关闭；启用后显示阈值与“词频缺失如何处理” | 解释 Zipf 是通用语料频率，不是学习价值或 OCR 正确率 |

预设只作为快捷填入规则：**当前默认**、**精简候选**和**自定义**。点预设后展示具体被启用的条件、各层新增排除数与最终数量，仍需点“应用规则”才改变正式词单；不能把“报告式严格规则”当作不透明的一键提交。

右侧顶部固定显示“40 个候选 → 预计保留 18、排除 22”，并列出本次相对已应用规则的增减。列表用“预计保留 / 预计排除 / 人工决定”三个视图；每词标出具体原因，例如“低于所选 JLPT 范围”“只出现 1 次”。同时命中多条规则时可以展开全部原因；各层排除数只计算该层**新增**排除，避免重复计数。搜索与排序明确写成“仅调整列表显示”，不触发选词。

底部固定动作：未修改时显示“规则已应用”；修改后显示“尚未应用 · 预计保留 18 词”，提供“撤销改动”和主按钮“应用规则，保留 18 词”。应用成功后提供“继续：AI 语境筛选”和“跳过 AI，手动筛词”。

### 第 2 步：AI 语境筛选

首屏只放任务选择：F1/F2/F3 使用用户语言说明“清理明显噪声 / 看原句判断 / 两轮复核”，同时给出预计批次数、可能产生的待审项和所选模型。并发放入“运行设置”，默认 2；服务限流时提示可降为 1。主按钮写“开始筛选 X 词”，旁边明确提供“跳过 AI”。

运行中保留结果列表，顶部显示“已判断 24/40 · 暂保留 8 · 暂排除 8 · 暂待审 8”，并注明**全部完成前正式词单不变**。取消后提供“继续剩余项”“只使用已完成判断”“放弃检查点”，每个动作说明未处理词如何处理。完成后进入手动筛词，不把模型的待审当成已人工批准。

### 第 3 步：手动筛词

顶部显示“准备处理 X 词 · 待审 Y 词 · 人工决定 Z 词”，默认先看待审。每词只有**手动保留 / 手动排除**两种人工操作；再次点击当前操作可撤销并回到自动结果。人工排除优先于保留。原句、出处与自动筛选原因是判断依据；这一步没有词卡字段编辑。

这里的主操作是“继续生成 X 词释义”。“当前列表全保留／当前列表全去除”直接显示在本步骤，不用逐词点击或展开菜单。范围为右侧当前视图、搜索和等级条件匹配的**全部词**，包括未显示的分页；若需处理整本书，先切到“全部”视图并清空搜索。操作立即保存，旁边提供“撤销上次批量操作”，恢复每个词原有的人工决定和入选状态。

### 第 4 步：AI 释义生成

R0–R3 与 F1–F3 使用相同的整行单选卡形式，名称和会生成的内容直接可见。翻译引擎放在档位下面；选 R1–R3 才显示 LLM 配置，并发收在运行设置里。主按钮是“生成 X 张释义草稿”。这一步只生成文字草稿：R0 直接翻译词语和原句，R1–R3 按批补语境词义、学习提示或复核；不处理漫画图片。

第 2、4 步点击后立即入主进程任务队列，可返回书库阅读或切到设置。右下角与 OCR 共用[任务队列弹层](../screenshots/18-anki-background-task-queue.png)，显示正在跑的书、进度和排队项，提供停止/取消与“打开制卡页”。任务完成或失败的结果留在弹层直到用户清除；返回书页后从落盘结果恢复词单或草稿。退出应用不会自动续跑，已保存的批次检查点仍可手动继续。

### 第 5 步：制卡

右侧选词并直接编辑卡面词语、读音、原句、词义、句译、用法、语气、来源文字和原图出处。编辑器置于详情顶部，原文证据与卡片预览可展开；修改后保存草稿，存疑卡可人工通过审核。若有存疑卡，进入本步默认打开“词卡待审”列表，逐张显示模型给出的原因；确认最后一张后回到完整词单，导出按钮变为可点击。按钮禁用时在旁边说明具体原因。左侧独立选择**不带图 / 文字框截图 / 整页漫画**，默认延续旧版的文字框截图；整页图等比压缩为 JPEG，相同页的多张卡只存一份。配图按书持久保存，切换不改变释义草稿，也不产生翻译或 LLM 请求。最后“制卡并导出”组装 `.apkg`；旧版 TSV 仍可单独导出。

## 状态与文案约束

- **规则草稿、已应用规则、LLM 临时判断、人工决定**分开显示。预览词表不能伪装成已保存结果；刷新页面恢复已应用规则，不恢复未应用的编辑草稿。
- 同一个词同时有自动排除和人工保留时，显示“手动保留 · 原因：仅出现 1 次”；有人工排除时显示“手动排除”。旧候选或词频缺数据用“无法判断”，不显示成低频。
- 把“已选”统一改为“准备制卡”，把“直接筛选”改为“规则筛词”，把列表搜索栏标题改为“查看词表”。`LLM`、`Zipf` 和并发数可保留在帮助或进阶设置中，主路径用结果导向文案。
- 不用仅靠颜色表示保留/排除/待审。控件要有清晰的键盘焦点、可读标签和状态提示；规则变化后的结果通过文字区域播报。实际对比度、屏幕阅读器和 200% 缩放需在实现后验收。

## 实现验收标准

1. 在 1366×768 的窗口内，用户不经过内部滚动即可看见当前步骤、预计保留数、主操作与通往下一步的路径；窄窗口没有横向溢出。
2. 修改任一规则后，数量、预计保留/排除列表和逐词原因立即一致；应用前正式选择与已有检查点不变。
3. 用户能在一处完成手动保留/排除，并能辨认自动决定与人工覆盖。改规则遇旧检查点时不会静默丢弃。
4. 不配置 LLM 时，可以从规则筛词直接到手动筛词、选 R0 生成译文；运行 LLM 时，临时结果和最终结果有明确区别。
5. 搜索、排序和列表视图切换不改变准备制卡的词单；批量修改动作显示具体影响项数。
6. 修改配图模式不改变 R 档位或既有草稿、不产生外部请求；第 5 步能保存全部可见卡面字段，并以三种配图方式导出。
