# 漫画与图片批注图层

核对日期：2026-10-05。第一版支持漫画、图片文件夹及用漫画阅读器打开的图片型 EPUB；文本 EPUB 阅读器暂不支持。

## 使用方式

- 底部提供带图标及文字的“阅读／选择／画笔／橡皮擦／文字”。工具选择不创建图层；画笔复用当前可写画笔层，没有时第一笔与新层一起保存。“文字”点击空白处放置草稿，提交非空内容时才建层；取消或空草稿不留下空层。自动建层和第一份内容只占一次撤销；管理区显式“＋图层”仍允许创建空层。
- “橡皮擦”只擦当前选中画笔层在当前页的完整笔划，不自动猜测其他目标；当前选中的是文字层、当前页没有笔划、图层隐藏/锁定或页面失配时不可用。切换工具先提交文字及进行中的笔划，重复点击同一工具保持现状。
- 右键页图，选“新建画笔图层”或“新建文字图层”，会自动进入编辑。文字编辑框放在点击的位置，靠近页边时向页内调整。
- 右上角按“沉浸 → 侧边栏”排列。“侧边栏”打开右侧面板，提供“词卡夹／图层管理”两个标签；词卡数量放在词卡夹标签内。默认显示词卡夹，同一阅读会话收起后重新展开会保留上次标签。右键“管理图层”直接展开图层管理标签。
- 沉浸右上角复用上述工具，以纯图标呈现并提供名称、提示和键盘焦点轮廓；另有系统栏、侧边栏及退出沉浸按钮。鼠标靠近右上角或键盘焦点进入时显示，编辑或侧栏打开时保持可见。鼠标图标提交草稿并返回阅读，继续保持沉浸；退出沉浸是独立按钮。悬停保持深色背景和白色图标。
- 系统栏独立开关，覆盖漫画而不改变阅读窗口尺寸；文字输入不再自动切换全屏/最大化。草稿跨失焦保留，window focus 不抢回输入焦点；系统栏按钮的指针按下不转移 HTML 输入焦点。退出沉浸恢复进入前窗口和系统展示状态；F11 同步退出界面沉浸。
- 底部 OCR 控件下面提供“批注图层”总开关、快捷工具、编辑参数、撤销/重做及保存状态；图层列表、显示/锁定、改名、排序、清空和删除在右侧管理，仍保留管理区创建入口。每本书统一管理画笔/文字图层，内容按页图 URL 保存；双页模式点击任一页图，会切换管理区标明的当前操作页。侧栏占据独立布局空间，关闭/切换标签保留批注及编辑工具状态。
- 管理区可改名、显示/隐藏、锁定、编辑、调整顺序和删除。列表上方的图层覆盖下方图层。原图、批注、OCR 文字命中层、弹窗按此顺序叠放。
- 画笔支持颜色、粗细、不透明度与整笔橡皮。橡皮只移除当前图层命中的完整笔划。撤销/重做按书记录最近 50 次操作，含笔划、文字及图层管理；历史不写盘，重新读取后清空。
- 文字是纯文本，支持多行、颜色、字号、不透明度、背景色及横/竖排。文字工具点击已有可写文字立即修改；选择工具可直接选中并拖动任意可写层的笔迹或文字，无需先到管理区选层。双击文字修改，右下角调整文本框宽高，不改变字号。Enter 换行，Ctrl/Cmd+Enter 提交、Esc 取消本次修改，二者保留当前工具；空的新文字及自动层不保存。提交已有文字为空会删除该对象。
- “阅读”或“返回阅读”退出批注；阅读状态不接管鼠标，OCR 查词、划词及翻页正常。编辑状态停用 OCR 命中与边缘翻页；中键或空格加拖动平移。翻页、单双页/偏移切换提交草稿后返回阅读。输入框内 Esc 优先取消草稿，组合输入期间不执行提交/取消。
- “清空本页”只清空指定图层在当前操作页的内容；“删除图层”删除该图层全书内容。两者分别确认范围，均可在当前会话撤销。

画笔粗细、文字字号和几何使用原图像素。SVG `viewBox` 与原图尺寸一致，显示时跟随图片缩放、平移、阅读方向及双页布局；每张图捕获自己的手势，跨接缝的笔迹夹在起始页边界内。批注无需 OCR 数据。

## 沉浸技术方案（2026-10-05）

原方案把 `autoHideChrome` 映射到原生全屏；Windows 文字草稿开始/结束又切到无标题栏最大化/原生全屏，工作区扣除任务栏导致漫画重新排版。现方案保留前端沉浸偏好，原生窗口几何、系统栏、批注工具各自独立。

| 平台 | 沉浸窗口 | 系统栏开关 | 退出恢复 |
|---|---|---|---|
| Windows | 当前显示器物理范围的普通无边框窗口；去掉标题、边框、Tao 阴影内边距和调整大小能力，Win32 `SetWindowPos` 精确覆盖整屏；不置为全局置顶 | 仅标记自己的 HWND：`ITaskbarList2::MarkFullscreenWindow` 与 `NonRudeHWND`，让 Explorer 决定任务栏在上或在下；不修改全局任务栏设置 | 保存/恢复原生窗口样式和 `WINDOWPLACEMENT`（包含最大化前位置），恢复原生菜单、阴影及可调整大小状态，清理系统栏标记 |
| macOS | Tauri `set_simple_fullscreen`，当前 Space 内覆盖当前屏幕，避免进入原生全屏新 Space | 主线程设置 `NSApplication.presentationOptions`；隐藏用 `AutoHideDock | AutoHideMenuBar`，显示恢复进入前选项；窗口范围不随按钮改变 | Tauri 恢复原窗口样式、范围、移动能力及进入前 presentation options |

Windows 的“显示系统栏”是恢复系统正常展示规则；若用户已设任务栏自动隐藏，仍保留该偏好。macOS 也保留 Dock/菜单栏原有自动隐藏设置；隐藏状态允许靠近屏幕边缘临时出现。切换其他应用不永久隐藏系统栏。应用“文件／编辑／视图”菜单和系统任务栏是两个不同对象：Windows 沉浸始终隐藏应用菜单，系统栏按钮只管理任务栏覆盖。Linux 暂用无边框整屏，未接入桌面环境的系统栏控制。

窗口操作在原生 UI 主线程串行执行；前端串行发送最新状态，避免快速开关请求乱序。文字焦点和草稿不触发窗口 API。批注状态只有 `read / select / pen / eraser / text`；草稿与指针手势是工具内部临时状态，切换工具、翻页或退出阅读器提交，取消新草稿不落盘。工具选择、系统栏按钮、侧栏入口和退出沉浸各有明确职责。

参考：[Microsoft 的全屏标记 API](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-itaskbarlist2-markfullscreenwindow)、[NonRudeHWND 的系统判定行为](https://devblogs.microsoft.com/oldnewthing/20250522-00/?p=111211/)、[Apple 的应用展示选项](https://developer.apple.com/documentation/appkit/nsapplication/presentationoptions)。macOS 实现已按本地 Tauri/Tao/objc2 API 核对；本机没有 macOS 运行环境，不能视为运行验收。

## 保存与异常

文件位于 `<userData>/library/<bookId>/comic-annotations.json`，不在 `content/` 内，不修改图片和 `manga.json`。已完成的笔划、文本编辑及管理操作立即进入串行保存泵，以临时文件、fsync 和 rename 原子写盘；后一个请求使用前一个响应的最新 revision，旧响应不覆盖较新的本地修改。

状态栏显示加载、保存中、已保存或错误。写失败保留本地文档及撤销栈，可重试；离开阅读器/OCR 导致组件重建也继续保存。存在待保存修改时阻止正常关闭，关闭检查会先提交当前文字/笔划。强杀进程、断电时尚未到达磁盘的编辑不保证恢复。

revision 冲突拒绝覆盖其他窗口的修改。本地修改保留，但重试不会自动合并；“重新读取”在确认放弃未保存修改后恢复磁盘版本。坏 JSON、不支持的版本和读取错误报告错误并保留原文件，不能以空文档覆盖它；文件损坏时需从自己的备份恢复后重新读取。

含批注的页面绑定原图尺寸和 SHA-256。读取或保存时核对原图，重新进入阅读器会重读已保存状态。页面文件消失、尺寸变化或内容变化会标记失配并隐藏旧批注；该页提示“清空本页旧批注”，确认后移除所有图层在该页的旧内容，再用新原图绘制。其他页及图层名称、顺序、可见性保留。失配页面拒绝新增/修改旧内容，清空后也不能通过撤销把旧批注悄悄绑定到新图。当前没有文件监听，阅读中外部替换原图需重新进入/读取后更新提示。

第一版不将批注并入 OCR、分词、词卡原文或 Anki 配图；不提供压感、富文本、图层合并、图片导出、云同步与 EPUB 文本锚定。界面最多创建 100 个图层；主进程另校验对象、点数、文本数量和几何上限。

## 实现入口

| 代码 | 职责 |
|---|---|
| `src/shared/annotations.ts` | 图层、笔划、文字和页面绑定的 v1 契约 |
| `src/core/comic/annotations.ts` | 数据校验、原图坐标转换、橡皮命中 |
| `src/core/comic/annotation-store.ts` | 保存泵、revision、撤销/重做、错误与重读状态 |
| `src-tauri/src/annotations.rs` / `storage.rs` | 书籍/路径校验、原图签名、失配保护、原子存储 |

| `src-tauri/src/system.rs` / `App.tsx` | 原生沉浸窗口、跨平台系统栏展示、窗口状态恢复及串行请求 |
