## 原方案的基础与缺口（迁移前记录）

- 漫画按页内文字块生成 `segments.json`；每个 token 保留表面形、辞书形、块内 UTF-16 位置、是否命中词典。去重词表目前只保留辞书形、次数、最多 8 个表面形。
- `core/dict/lookup.ts` 的词典驱动贪心最长匹配仍供阅读时点词扫描使用；整书批量词表已改用 Kuromoji，不再因词典缺词而逐字切分。
- `SegmentView` 可生成/重生成、搜索、筛选已命中词典；只展示前 400 项，未提供分页、原文预览、选择状态或导出。
- 现有 `cards.json` 是用户手动保存的阅读词卡；没有 Anki 导出。不要让批量候选直接写入用户的已保存词卡。
- 项目已经依赖 `kuroshiro-analyzer-kuromoji` 处理日文路径，间接使用 Kuromoji。可复用或显式依赖其形态分析器，但仍须在真实漫画文本上对比质量、包体积和 Windows 路径行为。

## 产品定义

用户路线：打开漫画 → 确认文字层/OCR → 生成候选 → 按 JLPT/频次筛选 → 查看出处和词典释义 → 勾选、纠错或排除 → 预览 Anki 卡 → 导出 UTF-8 文本文件 → 在 Anki 导入。

“词语”是由分词器给出的可去重词条；“短语”是用户从原文中框选或合并相邻 token 保存的表达。短语不强行套单词的 JLPT 等级，包含词可以分别显示等级。

默认将“至少 N3 难度”解释为 N3、N2、N1；“至少 N2 难度”为 N2、N1。最终文案用“包含 N3/N2/N1”，避免“以上”方向歧义。JLPT 来源没有覆盖或匹配不确定时显示“未知”，不能当作 N1 或简单词直接过滤掉。

## UI/UX

### 入口与页面

沿用漫画阅读器已有的“分词”入口，不新增顶层导航。页面分为：

1. **准备区**：文字来源（已有文字层/系统 OCR/扩展 OCR）、页数、文字块数、词典与 JLPT 数据源状态；缺文字时给出“先识别文字”的动作。词典尚未载入时禁用批量生成，给出具体原因。
2. **筛选条**：难度选择 `全部 / N5 / N4 / N3 / N2 / N1 / 未知` 和快捷范围 `N3–N1 / N2–N1`；出现次数、搜索、只看未加入、排除词典未命中；显示每步过滤后的数量。
3. **候选列表**：词语/读音、JLPT 徽标、出现次数、原文截句、页码、已选/已排除状态。默认按“出现次数较高 + 未制卡”排序；允许按页序、等级排序。超过 400 项使用分页/虚拟列表，不静默截断。
4. **审核侧栏**：一条候选的辞书形、读音、词典义、多个出处；当前例句高亮目标词，允许改 OCR 原文、选代表例句、合并/拆分为短语、手动改读音和等级。可跳回漫画页核对。
5. **制卡清单**：已选数量、重复/缺读音/缺释义/文字可疑数量；导出前预览正反面，逐项排除或返回纠错。重复导出给出“跳过已导出/全部重新导出”选择。

状态要明确：未识别、生成中（进度/取消）、生成失败、无候选、JLPT 数据缺失、候选需审核、可导出。即使 OCR 或 JLPT 缺失，仍应能手工加入短语，但不能宣称自动筛选可靠。

### 首版 Anki 卡内容

- 正面：词语或短语 + 读音；反面：简短词典义、漫画原文例句、书名/页码。
- 标签：`aralebook`、书名标识、`jlpt_n3` 等；未知等级不写等级标签。
- 同一词条的多个出现位置只导出一张卡，用户选代表例句。去重键至少包含规范化辞书形和读音；异读/异义必须能人工拆开。
- 首版导出 UTF-8、制表符分隔的 Anki 文本文件。第一列是稳定可见的“词语（读音）”，方便 Anki 的首字段去重；第二列为卡背文本，第三列为标签。把换行和制表符安全编码，避免错列。首版不自动嵌入漫画截图或音频。

## 技术方案

### 1. 分词质量

定义 `Tokenizer` 接口：输入一个文字块，输出 `surface / lemma / reading / pos / [start,end)`。先在同一批人工标注的漫画文字块上比较现有最长匹配和 Kuromoji，重点看动词变形、助词粘连、拟声词、人名、跨行 OCR、假名异读。达到基线后用形态分析做候选切分，现有 Yomitan 词典继续负责查词和释义。

Kuromoji 提供词性、基本形和读音，但词典识别的“词”和真正有学习价值的“短语”不完全一致。自动候选只提取内容词及明确的复合词；句型、惯用语、跨块组合保留给人工合并。对未知语与单汉字占位降低优先级，不能静默丢弃。

偏移一律相对原始 OCR 文字块，以 UTF-16 `[start,end)` 保存；词形归一化只用于匹配，不覆盖原文。重生成 `segments.json` 时写入算法/词典/JLPT 数据集版本，旧产物提示过期。

### 2. JLPT 数据

JLPT 官方公布 N1–N5 难度说明，但没有发布可当作权威答案的词汇清单。采用可追溯的社区词表，并在 UI 标记“参考等级”。候选源是 `stephenmk/yomitan-jlpt-vocab`；其 README 明确指出数据来自 Jonathan Waller、等级是估计、源数据有 CC BY 条款，仓库标有 CC BY-SA 4.0。正式内置或分发前需要核对具体数据文件的许可、保留来源/版本/署名；也可先支持用户导入此类数据。

内部索引键优先 `规范化表记 + 读音`，仅表记命中且存在多读音时标记“待确认”。一词落在多个社区等级时保留来源与冲突，默认显示最容易的已记录等级并标注冲突，不伪造精确等级。未知单列，不映射到 N1。

### 3. 候选与选择数据

`segments.json` 继续作为可重生成的机器产物；新增每书的用户选择/纠错文件（建议 `study-list.json`），与 `cards.json` 分开。记录候选键、用户编辑后的词/读音/例句、出处 ref、选择/排除/导出状态和数据集版本。写入必须原子化，重分词时按稳定键迁移人工选择；匹配失败的修改列出待处理，不直接覆盖。全局已导出索引可在第二阶段加入，首版至少书内去重。

主进程增加候选查询、编辑/选择、预览、导出 IPC；渲染进程不直接读书库文件。导出逻辑放主进程纯函数，可对字段转义、顺序稳定性和重复导出做单测。批处理分批让出事件循环，沿用现有进度与取消模型。

### 4. Anki 交付边界

Anki 官方支持 UTF-8 的逗号、分号或制表符分隔文本；可映射标签列，通常按首字段判断重复。CSV/TSV 不会自动打包媒体：若要漫画截图，需要生成文件、复制到 Anki 的 `collection.media` 并在字段中引用，或后续实现 `.apkg`。首版先用纯文本卡验证切词、审核和导入，再决定媒体包方案。

## 实施顺序与验收

1. **词表基线**：抽样至少数页真实漫画，人工标出分词、读音和应制卡词，比较现有算法与 Kuromoji；确认分词器、许可证和词表版本。
2. **数据管线**：新增富 token 与 JLPT 索引，保留原文偏移，词典匹配和候选去重；覆盖同形异读、未收录、OCR 错字和重分词迁移测试。
3. **审核体验**：扩展 `SegmentView`，完整列表、筛选、出处、纠错、制卡清单；验证空状态、长书性能和键盘操作。
4. **导出**：纯文本 Anki 文件、导入说明、去重与重复导出测试；在 Windows/macOS 的 Anki 中手工导入检查日文编码、字段映射和标签。
5. **后续**：截图/音频、`.apkg`、跨书去重、用户已学词过滤、按用户水平推荐与自动短语发现。
