# 漫画 Anki 筛选与制卡 Harness

核对日期：2026-10-02。入口为漫画“分词 → Anki 制卡”；候选、生成计划与人工审核保存在每书 `study-list.json`。新建任务默认 A3，旧 R0–R3 数据与任务保留兼容。词典由用户手动导入，本轮没有增加自动下载或内置通用词典。

## 当前 A0–A4 流水线

页面保留五步：规则筛词 → 可选 F 筛词 → 人工选词 → 证据生成/修复 → 制卡。完整 F 筛选的存疑词可以先进入新 A 流水线，其风险会保留在词卡审核中；旧 R 路线仍保留原审核门槛。F 筛词是可选的独立任务，其 token 不计入 A 生成阶段预算。

| 步骤 | 算法 | LLM | 翻译 |
|---|---|---|---|
| 候选生成 | Kuromoji 切词与原文跨度、词频/JLPT、统计全部出现；从全部出处保留评分最高的五处 | 无 | 无 |
| 学习价值选择 | 原有规则、人工例外与阅读优先度；新增每次处理卡数限制 | 可选原有 F1–F3 | 无 |
| 选句与证据 | 按长度、终止符、异常字符和有效跨度选句；尊重人工锁定出处。每次运行读取当前启用词典 | 不用模型决定真实原文 | 无 |
| 核心字段 | 词典精确词形/读音及假名空读音兼容；唯一读音可补入草稿 | A2 疑难项、A3/A4 全量生成中文语境词义和句译 | A1/A2 本地项只翻译原句，同句共享 |
| 校验修复 | ID、字段类型、原句跨度、证据引用、截断和异常字符检查 | A3 风险卡复核，A4 全量复核；存疑项最多一次换备用例句/补备用证据重生成，A3/A4 再复核修复结果 | 翻译错误中断并保留检查点 |
| 审核导出 | 字段级问题、已通过/待审/暂缓分流；只导出已通过卡并更新这些候选的导出标记 | 无 | 无 |

例句评分只用于挑选，不是 OCR 准确率。没有可靠漫画阅读顺序时，不自动拼接相邻文字框；复核/修复使用同词备用出处。旧词单最多仍只有原先五处，重新生成候选才能获得整书优选结果；旧记录中非首个 `contextRef` 按人工选句保守锁定。手动词义单独标记并作为证据，候选人工内容不会被词典刷新覆盖。

| 档位 | 生成与复核 | 配置 | 消耗 |
|---|---|---|---|
| A0 本地词典 | 词典参考释义，无句译；多义/缺证据/缺读音仍待审 | 无外部配置 | 0 LLM、0 翻译 |
| A1 翻译辅助 | 词典参考释义＋同句共享句译 | 翻译 | 0 LLM，按不同原句调用翻译 |
| A2 节省 AI | 单条、短、非多义且无程序风险的参考项用本地＋翻译；其它项 AI 生成，存疑最多修复一次 | LLM＋翻译 | 只对疑难项使用 LLM；复杂/英文词典可能使大部分项都进入 AI |
| A3 标准 AI | 全量生成词义/句译，程序或模型风险项复核，有限修复并再核查 | LLM | 每批 6 卡生成，动态复核和修复另计 |
| A4 深度 AI | 全量生成与复核，更多备用原句证据，可添加一条简短学习提示 | LLM | 每批 6 卡生成＋复核，修复另计，最高消耗 |

A0/A1 和 A2 本地项标记为 `referenceOnly`：单义参考条目能直接进入已通过区，但不声称算法确认了语境义。生成与复核使用同一所选模型，复核能看到草稿，不是不同模型的独立质量证明。无词典支持的 AI 释义即使模型声称通过，也保留待审；不虚构证据。没有通用释义词典时会产生较多待审，不能用更高档位代替缺失的资料。

### 词典与输出契约

`lookupTerms` 提供多个带来源的匹配条目；日汉双解中假名词的空读音可按假名等价匹配，汉字未知读音不随意回退。明显的圈号义项可拆成条目片段，其余保留条目级；每个候选最多四个词典条目、十二个证据片段，每片段最多 900 字，截断与多义提示保留。程序不会假称已完整解析所有 Yomitan 词典的义项结构。

`submit_anki_pipeline` 输出中文词义、句译、用法/语气、`evidenceIds` 和 `issues`；`verify_anki_pipeline` 输出字段级问题。字段与问题类型由程序严格检查，错 ID/漏项/格式或上下文超限拆小批次，单项仍失败则停下。可选提示存疑时删除提示，不阻断可靠核心字段；词义、读音、原文、句译风险进入待审。

`status` 分为 `ready`、`needs_review`、`deferred`。手动更换草稿出处会重置审核；A0 无需补句译即可人工通过，其余档位要补词义和句译，汉字卡还需读音。新 A 档位导出不会因其他待审卡被全局阻断；稳定 GUID 用于后续增量重导，但 Anki 客户端更新语义仍需验收。

### 数量、预算与续跑

- “本次新增卡数”按阅读优先度挑选尚未完成的词，已完成卡保留，其余暂缓；下一次可继续。
- `study:previewCards` 只读当前候选和词典，显示 AI 项数、不同翻译原句数、基础生成输入字符估算与输出上限，不产生外部请求。预览按全部已选词计算，不含动态复核、修复、推理与重试；不是精确价格或质量承诺。
- 生成阶段预算至少 1000 tokens，留空不限；预算模式批次并发固定 1，不限预算沿用 1–3 并发。单次输出设置上限，协议重试也检查剩余预算；每次调用和实际/估算用量落盘。没有完整 usage 时，按输入估算＋输出上限保守记账，不能把未知当零。服务端真实用量可能超过估算，预算不是精确计费硬上限。
- 预算不够先缩小待处理批次，单项仍不足或未完成本档位复核/修复的卡暂缓。提高同计划预算后复用已完成卡，只处理暂缓项。已通过卡可先导出，不降低核查标准。
- 计划指纹包含流水线版本、候选输入、所选原句、词典证据及 LLM/翻译配置签名。同 ID 的模型/端点/密钥变更也会被识别。不同计划不能混用已有待完成检查点；页面提供明确放弃后重新生成入口。队列还校验排队期间的翻译配置变化。
- 词典证据和句译缓存按书保存；A1/A2 相同原句的翻译只调用一次，已通过的 AI 卡复用同句句译。当前 AI 输出仍按卡返回句译，不宣称已经消除了所有重复输出 token。

本轮没有自动学习已掌握词的模型，也没有接入 Anki 已学状态同步、视觉模型核对、独立复核模型或自动漫画跨框排序。审核量与整卡正确率仍需固定人工样本对比；自动通过和自动排除项都要抽查。

## 页面流程

1. **规则筛词**：左侧按“学哪些等级、排除哪些明显无用词、只保留重复词、参考通用词频”改规则，右侧立即预览“候选 → 预计保留/排除”及逐词原因；点击应用才修改正式词单。N5–N1 独立复选，默认 N3/N2/N1；未收录和等级冲突可以分别选择，旧书的合并设置仍兼容。新增词性、专名、数词、分词器未知词、每书排除词、次数和词频规则默认关闭。“精简候选”只填入核心词性、专名/数词排除和至少出现两次，仍需应用；Zipf 仍由用户单独启用。JLPT 只是社区参考，不代表用户真的掌握某级词。
2. **AI 语境筛选（可跳过）**：从已应用的规则结果开始，选择 LLM 配置和 F1/F2/F3，点击后立即加入主进程任务队列，可离开制卡页。每批返回 ID、决策和一句理由，页面与右下角任务队列显示进度；**全部完成前不改正式选择**。格式错时自动拆半；中断后可续跑，也可明确选择“只使用已完成判断”：已判 `keep/review` 入选，已判 `reject` 和未处理项暂不制卡，检查点保留。已有检查点时，人工改词和重新生成候选需先续跑或明确放弃，避免输入变动使续跑失效。
3. **手动筛词**：优先显示 AI 待审词；看原句和原因后可逐词“手动保留 / 手动排除”，也可直接对右侧当前列表一键全保留或全去除，作用于全部匹配项（含其他分页），并支持撤销上次批量操作。完整 AI 筛选的待审词须人工处理后才能继续；只使用已完成判断的快捷路径仍可制卡，未处理项暂不制卡。
4. **AI 释义生成**：R0–R3 像 F 档位一样用单选卡选择；翻译引擎与 R1–R3 的 LLM 配置放在下面。点击后立即加入相同的后台队列。R0 仅翻译词与原句，不调用 LLM；R1–R3 按批生成语境解释，格式错时拆半重试，已完成批次可续跑。漫画配图不参与这一步。
5. **制卡**：逐张修改词语、读音、原句、释义、句译、用法、语气和出处，复核存疑卡；独立选择“不带图 / 文字框截图 / 整页漫画”。配图更改不重跑翻译或 LLM。最后组装导出 `.apkg`，旧 TSV 路线保留；候选/选择已变化、配图失败或缺出处时拒绝导出旧草稿。详细交互见[筛选 UX](anki-filter-ux.md)。

## 档位与选择依据

| 档位 | 做什么 | 额外 LLM 调用 | 适合 |
|---|---|---:|---|
| F1 快速排噪 | 每批 12 词，剔除明显乱码、纯专名或无意义片段；存疑保留 | `ceil(候选/12)` | 候选多、只想先去噪 |
| F2 语境筛选 | 每批 8 词，逐项检查词形、读音、原句和 OCR 疑点 | `ceil(候选/8)` | 更重视语境，能接受更多输出 |
| F3 双轮复核 | 每批 8 词，筛选后再请求复核；意见冲突变待审 | `2×ceil(候选/8)` | 错删代价高，愿意人工处理分歧 |
| R0 翻译释义 | 翻译目标词和原句；配图另选 | 0；每词最多 2 次翻译 | 最快、无 LLM 配置 |
| R1 语境词义 | 每批 6 卡，在 R0 基础上生成本句词义 | `ceil(卡数/6)` | 需要中文语境解释 |
| R2 学习提示 | 每批 6 卡，加一条有价值的变形/搭配/语气提示 | `ceil(卡数/6)` | 想看简短用法 |
| R3 生成＋复核 | 每批 6 卡，生成后独立请求复核；存疑卡进人工审核 | `2×ceil(卡数/6)` | 重视卡片可信度 |

以 200 词/卡为例，正常调用数从旧的 F2 200、F3 400、R1/R2 200、R3 400 降到 **25、50、34、68**。若模型输出漏 ID、重复 ID、非法 JSON 或报告上下文超限，仅拆分出错批次，实际调用会增加；单项仍不合格时停下供用户换模型或修正。鉴权和普通网络错误不会盲目拆批。批处理减少请求往返和重复指令，但原句和每张卡的内容仍要传输，不能按请求数等比例推断 token 费用下降。
这里的“批处理”是在**一次普通 Chat Completions 请求里放多项**，可继续使用现有 OpenAI 兼容配置。它不是某家供应商专用的异步 Batch API；例如 [OpenAI Batch API](https://platform.openai.com/docs/api-reference/batch/object) 要上传 JSONL 并按最长 24 小时的窗口异步执行，不适合作为本地即时交互的唯一实现。

筛选、释义和复核共用一套 `items` 结果 schema；DeepSeek 标准地址默认用 JSON Output、OpenAI 官方地址优先严格 JSON Schema，其他兼容端点先尝试指定提交工具，格式不兼容再降级。所有结果都要通过候选 ID、数量和字段校验。协议细节、真实 HTTP 次数与缓存 token 统计见[LLM 结构化返回协议](llm-output-protocol.md)。F1–F3、R1–R3 每本书可选 1/2/3 个在途批次，默认 2；全应用 LLM HTTP 在途上限 4。R0 仍顺序翻译，避免一次把翻译端点推满。并发批次独立落盘，失败时中止新批次并等待已在途工作结束；成功后卡片恢复原候选顺序。并发只可能减少等待时间，真实加速和限流表现需按所选服务实测。

F1–F3 与 R0–R3 的**书级任务**由 `src/main/study/task-queue.ts` 串行执行，避免多本书同时跑模型或翻译；上面的 1–3 并发是同一本任务内的批次并发。入队 IPC 立即返回，任务不依赖制卡页是否打开。主进程保存运行中、排队与最近完成/失败/取消的快照，右下角与 OCR 共用“任务队列”入口，可停止、取消排队、回到原书或清除结果。同一本书同一请求去重；排队时若输入词单变动，开始前会失败并提示重新提交。关闭应用会终止内存队列，不会自动续跑；已落盘的批次检查点仍可在重开后手动续跑。
批量大小参考了本机 `manga_anki` 已导出的 232 张卡：已审核例句长度中位数 10 字、95 分位 21 字、最长 37 字。这只说明该样本适合小批量，不保证其它漫画或模型的上下文容量。异常长的 OCR 块只把目标词附近最多 320 字送入 Harness，词典释义提示最多 350 字，译文最多送 600 字；原文/译文被截断的卡自动标为待审，完整原文仍保留在候选和卡片中。

F3/R3 的第二次调用目前使用**同一套所选模型**，不是不同模型的独立交叉验证。档位表示流程和调用量，不宣称准确率按档位递增。翻译服务目前仍按文本调用；不同提供商没有统一的批量接口，同句缓存可减少重复网络请求。实际耗时和费用还取决于用户选择的服务，不在 UI 中伪造固定价格。
每次完成后界面显示实际 Harness 调用次数和耗时；翻译计数是服务调用次数，可能命中缓存，不等于外部计费请求数。

推荐先用**规则筛词＋R0**看翻译草稿，在第 5 步按需要选择无图、文字框或整页配图；想减少错义卡时试 R1。若用户愿意做逐卡语境筛选，F2 比 F1 更细；F3/R3 需要对样本评测后才可宣称收益。

## 如何评价档位

在同一部漫画中固定 150–200 个候选，覆盖各 JLPT 等级、未分级、同形异读、拟声词、人名、OCR 错字、口语缩约与只出现一次的词。人工独立标注“值得制卡 / 应排除 / 需复核”，并标正确的原句词位、词义、读音、句译及截图框。

分别报告：筛选 precision、目标词 recall、**错删率**、待审占比；词卡的词形/读音/语境词义/句译/配图各项正确率及整卡全对率；每张被人工接受的卡的模型调用数、实际耗时和费用。先比较 F1/F2/F3 与直接筛选，再比较 R0/R1/R2/R3；评估集不参与调提示词。模型输出自报的“置信度”不能代替人工标注。最终用 Anki 桌面版检查首次导入、再次导入是否保留身份、媒体显示和用户修订更新行为。

## 直接筛选与参考报告的对应

参考 [本机作品的词汇筛选报告](/Users/heyanle/Desktop/project/manga_anki/projects/0001-kyou-wa-kanojo-ga-inaikara/reports/vocabulary-selection-workflow.md)：报告先清洗 OCR 与分词，排除专名、数词、停用词和未知词，再聚合 lemma/读音、书内出现次数与跨页数，结合通用词频和人工例外决定候选，最后人工审核。应用目前使用 Kuromoji 而非报告的 Sudachi B，所以细分词性和未知词判定可能不同；旧候选缺少元数据时保守保留，重新生成候选才能完整应用这些开关。报告里的作品人名、停用词和需排除的 OCR 页属于该作品，不能直接复制到所有书；每书排除词和逐词手动保留承担人工例外。报告中的复合资格条件和“已策展词”需要专门词表，本版提供独立开关与严格预设，并不声称复刻报告最终卡组。

Zipf 参考表在构建期从 `wordfreq 3.1.1` 的日语 large 列表生成，运行时只读取包内 gzip JSON，无需用户 Python。查询候选基本形和已保存的表面形，取可查到的最高值；查不到记为“未知”，不自动当低频。分值 `3 log2(1+出现次数)+log2(1+跨页数)+max(0,2−|Zipf−4.5|)` 只用于“阅读优先度”排序，不用于自动排除。词频数据来源、署名和许可见 [WORDFREQ-ATTRIBUTION.md](../data/WORDFREQ-ATTRIBUTION.md)；上游许可说明见 [wordfreq NOTICE](https://github.com/rspeer/wordfreq/blob/master/NOTICE.md)。

## 当前实现与边界

- `src/core/study/harness.ts` 固定了 Harness 提示、输入 JSON 和结果校验；OCR 文本被明确当作不可信数据。API key 仍留在主进程的 LLM/翻译服务。
- `src/core/study/harness-tool.ts` 定义三种提交 schema；`src/main/study/concurrency.ts` 管每书并发，`src/main/llm/service.ts` 管全应用请求槽与兼容回退。候选和每书工作流在 `study-list.json` 持久化；改动直接规则遇到已有 LLM 检查点时会提示先续跑或明确放弃，避免静默丢失。
- `src/main/study/apkg.ts` 用 `sql.js` 和现有 `fflate` 生成 `collection.anki2`＋按需媒体；固定 deck/model ID 和每词 GUID。卡面支持逐卡覆写词语、读音、原句、译文、用法和来源文字；图片名取内容哈希。
- 配图使用 Electron `nativeImage`，目前可靠支持 PNG/JPEG。文字框截图为 **OCR 块级**，不是词的精确像素框；整页模式把最长边大于 2600 像素的页等比缩小，以 JPEG 质量 86 编码，同页媒体复用；无图模式不生成媒体条目。自动图像和翻译在卡背标记“未经人工校对”。
- 失败或取消不会把未完成输出标成已完成；LLM 请求收到取消信号后中止，按同一输入指纹、档位和配置重试时复用已完成批次。翻译请求最多仍需等待该服务自己的超时。旧 `study-list.json` 可读，旧 TSV 导出仍在。
- 长任务每批发 IPC 事件；页面关闭后右下角继续显示进度，页面重开先从主进程读队列快照。批次判断与中断原因仍写入每书文件；“只使用已完成结果”仅改变当前选卡，后续同配置续跑仍会覆盖未处理项。剩余时间是基于已处理项的粗略估计。
- 尚未在 Anki 桌面客户端实际导入，也未在 Windows 上验证新版制卡流程；真实 LLM/翻译供应商的速度、价格和正确率需要上述人工评测。
